# automated_test measurement — chirp @ `c805525`

Partition: every release-bar `BAR-*` whose `verification_method` is `automated_test` (36 of 278). One row per
criterion, keyed by `bar_id`, with a `live_status` from the inherited vocab `{met, partial, missing, not_applicable}`
and an observation grounded in a named test at `c805525`.

## How this was measured

- Target: `Nousix-LLC/nswe-demo` at commit `c805525` (a clean checkout; HEAD == `c805525`).
- The repository's own test suite was **built and run** with its own toolchain (`cargo test`) against the workspace at
  `c805525`. Every native test executed and passed:
  - `crates/chirp-server` — 24 unit tests (`api::handlers::tests`, `error::tests`, `repository::in_memory::tests`) and
    20 integration tests (`crates/chirp-server/tests/api.rs`: `happy_path`, `errors`, `pagination`), all green.
  - `crates/chirp-types` — 18 unit tests (`api::tests`, `domain::tests`, `ids::tests`), all green.
  - `crates/chirp-frontend` — 41 native tests (`api::tests`, `compose::tests`, `error::tests`, `profile::tests`,
    `timeline::tests`), all green.
  - The `ferric` / `ferric-router` / `ferric-http` framework crates and the workspace doc-tests, all green.
- The server tests run the **assembled** server in-process against a fresh **in-memory** repository (`build_router` +
  `InMemoryRepository`, driven with `tower::oneshot` — no database, no network bind). A verdict that rests on durable
  persistence is noted as such: a passing in-memory test says nothing about restart survival.
- The `wasm-bindgen-test` browser tests in the frontend are **compile-only** (gated to `wasm32`, a dev-dependency) and
  were not executed in a browser. Where a criterion rests on rendered layout, viewport, contrast, or browser-navigation
  behavior, no executable automated test exists in the repository; it is judged by reading the sources and marked
  conservatively (`missing`) rather than optimistically.
- Grounding rule: a criterion is `met` only when a present test actually asserts the condition and passes; `partial`
  when a test asserts only part of it (or the asserting coverage is indirect/mechanism-level); `missing` when no test
  asserts it or the surface it needs is absent from the implementation at `c805525`.

The met/partial verdicts cluster on the implemented server core loop (posting, timeline, replies, likes, follows, public
profiles, handle rules) exercised by `crates/chirp-server/tests/api.rs` and the repository/types unit tests. The missing
verdicts cluster where the release bar expects a surface the product does not yet carry at `c805525` — real credentials
and the sign-in/recovery/sign-out/account-management flows that depend on them, profile editing and account deletion,
and the browser-rendered responsive/accessibility conditions for which the repository holds no executable automated test.
