## Public type surface

Imported via `use chirp_types::prelude::*;`. Three modules:

**`ids`** — opaque, type-safe identifiers and time:
- `UserId(u64)`, `ChirpId(u64)` — `#[serde(transparent)]` (serialize as bare numbers); `new`/`get`,
  `From<u64>`/`Into<u64>`, `Display` (`user-N` / `chirp-N`). Generated by a local `opaque_id!`
  macro so the id types stay byte-for-byte consistent.
- `Timestamp(i64)` — milliseconds since Unix epoch (UTC), transparent; `from_millis`/`as_millis`.

**`domain`** — entities + validated value objects:
- Value objects `Username` (1..=15 chars, ASCII alnum/underscore) and `ChirpText` (1..=280 chars,
  counted by Unicode scalar). Both validate via `parse()` → `Result<_, ValidationError>`, impl
  `TryFrom<String>` + `FromStr`, and use `#[serde(try_from = "String", into = "String")]` so
  **deserialization of an invalid value fails** (invalid states are unrepresentable on the wire,
  not just in constructors). Limits exposed as `USERNAME_MAX_CHARS` / `CHIRP_TEXT_MAX_CHARS`.
- `ValidationError` — library construction error (`Empty` / `TooLong` / `InvalidCharacter`), impl
  `std::error::Error` + `Display`. Distinct from the wire `ApiError`.
- Entities (all `#[serde(rename_all = "camelCase")]`): `User`, `Chirp` (with optional `reply_to`
  for threads), `Follow`, `Like`, and the `Timeline` aggregate (reverse-chronological `chirps`).
  Documented invariants: `Follow.follower_id != followee_id`; one `Like` per (user, chirp);
  denormalized counts are read-only to clients.

**`api`** — the REST contract DTOs:
- `Cursor(String)`, `SessionToken(String)` — transparent opaque wrappers.
- `Page<T>` — generic pagination envelope (`items` + optional `nextCursor`); `new`/`len`/`is_empty`.
- Requests: `LoginRequest`, `CreateUserRequest`, `CreateChirpRequest`, `TimelineQuery` (optional
  `limit`/`cursor`, absent fields skipped).
- Responses: `AuthResponse`, `FollowResponse`, `LikeResponse`; entity types (`User`, `Chirp`,
  `Page<Chirp>`) are reused directly where a response *is* an entity.
- Error contract: `ApiError { code, message, details }` (+ builder `new`/`with_details`),
  `ErrorCode` (`SCREAMING_SNAKE_CASE`), `FieldError`.

## serde field-naming convention (stable, explicit)

- **Object fields: camelCase** via `#[serde(rename_all = "camelCase")]` on every struct/enum
  (`createdAt`, `displayName`, `replyTo`, `authorId`, `likeCount`, `followerCount`, `nextCursor`,
  …). The JSON key is pinned by the attribute, not the Rust identifier — renaming a Rust field
  does not change the wire format. Rationale: the JSON contract is a deliberate, stable boundary
  both (Rust) ends and any external tooling agree on.
- **Opaque wrappers: `#[serde(transparent)]`** → ids/cursor/token serialize as the bare inner
  value.
- **Validated value objects: `#[serde(try_from = "String")]`** → validation runs on deserialize.
- **`ErrorCode`: `SCREAMING_SNAKE_CASE`** (e.g. `"VALIDATION_ERROR"`) — conventional machine code.
- **Timestamps: JSON numbers** (epoch-millis, UTC).

## Dependencies added (with justification)

Added to root `[workspace.dependencies]` and referenced with `.workspace = true`:
- **`serde = { version = "1", features = ["derive"] }`** — the single runtime dependency; the
  derive macros are what every type uses. Required to deliver a serde-serializable contract.
- **`serde_json = "1"`** — **dev-dependency only** in `chirp-types`. The types merely derive
  `Serialize`/`Deserialize`; choosing a concrete wire format is the consumer's call, so consumers
  are not forced onto `serde_json`. It is used only by this crate's round-trip tests.

Centralized at the workspace level (not inline in the crate) to match the existing
`[workspace.dependencies]` centralization pattern and to give the server (#8) and frontend (#9) —
both of which will import `chirp-types` and likely use serde — one shared version. No `uuid`/time
crate was added (see below). No server or wasm dependencies.

## Design decisions & open questions

Decisions (rationale captured in the crate README's "Design decisions & trade-offs"):
- **`u64` id newtypes, not UUIDs** — honors dependency-light; wire shape is a plain number; the
  newtype lets the representation change later without breaking the field contract. A `uuid` dep
  was considered and rejected.
- **No `data`/`meta` success envelope** — endpoints return the resource directly; only errors use
  the structured `ApiError`. An envelope was considered and rejected as unnecessary per-endpoint
  coupling.
- **`Timestamp` as epoch-millis i64** rather than an RFC 3339 string or `chrono`/`time` type —
  dependency-free, unambiguous (always UTC), trivially ordered.
- **Domain/DTO reuse** — responses reuse entity types where the response *is* the entity; dedicated
  DTOs only where the wire shape differs (inputs, pagination, action results, errors). Avoids a
  parallel-DTO duplication layer.

Open questions for downstream (#8/#9) — none blocking this crate:
- Auth is modeled minimally (`LoginRequest`/`AuthResponse` + opaque `SessionToken`); real
  credential exchange (password/OAuth) is deliberately out of the type contract and will be a
  server concern when #8 is specified.
- Endpoint routes in `api`'s doc table are illustrative; this crate fixes the types, not the URLs.
  The server work-item owns the final route shapes.
- If a future requirement needs opaque (non-sequential) public ids, the `UserId`/`ChirpId` newtype
  boundary allows switching the representation without changing field names.
